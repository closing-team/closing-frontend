# 중고거래 채팅방 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 최신 Figma `MKT006`을 기준으로 목데이터 상품·대화, 텍스트/이미지 전송, 이미지 미리보기, 실패/재시도가 동작하는 중고거래 채팅방을 구현한다.

**Architecture:** `ChatRoomPage`가 목데이터와 로컬 메시지 목록을 소유하고 `ProductSummaryCard`, 기존 `ChatBubble`, `ChatComposer`를 조합한다. `ChatComposer`는 입력·파일·미리보기·실패 payload를 캡슐화하고, `onSendMessage` 콜백을 데이터 경계로 사용해 작업 7에서 API로 교체할 수 있게 한다.

**Tech Stack:** React 19, TypeScript 6, Vite 8, Tailwind CSS 4, Vitest 4, Testing Library, jsdom

## Global Constraints

- 시각 기준은 Figma `1180:8376` (`중고거래_채팅`, 375 × 812), 기능 기준은 화면설계서 `1288:9209` (`MKT006`)이다.
- 웹 구현에서 Figma의 44px iOS 상태 표시줄은 제외한다.
- 실제 HTTP/WebSocket/SSE, 인증, 프로덕션 라우트, 상품 상세 라우트는 추가하지 않는다.
- 기존 공용 `TopBar`, `ChatBubble`, 아이콘, 색상·타이포 토큰을 재사용한다.
- 이미지 선택 상태는 입력창 위 56 × 56 미리보기와 삭제 버튼으로 구현한다.
- 공백 텍스트는 전송하지 않고, 이미지와 텍스트가 함께 있으면 텍스트를 이미지 캡션으로 전송한다.
- 실패 시 `메시지를 전송할 수 없습니다.`와 `재시도`를 표시하고 payload를 유지한다.
- 모든 프로덕션 동작은 실패 테스트를 먼저 작성하고 RED를 확인한 뒤 구현한다.
- Task 2 최종 변경은 `[채팅] feat: 중고거래 채팅방 UI 구현` 기능 커밋 하나로 정리한다.

```tsx
it("blocks blank text and clears a successful text send", async () => {
  const onSendMessage = vi.fn();
  render(<ChatRoomPage room={room} messages={[]} onSendMessage={onSendMessage} />);
  const input = screen.getByPlaceholderText("메시지를 입력하세요...");
  const send = screen.getByRole("button", { name: "전송" });
  expect(send).toBeDisabled();
  fireEvent.change(input, { target: { value: "   " } });
  expect(send).toBeDisabled();
  fireEvent.change(input, { target: { value: "안녕하세요" } });
  fireEvent.click(send);
  await waitFor(() => expect(onSendMessage).toHaveBeenCalledWith({ type: "text", content: "안녕하세요" }));
  expect(input).toHaveValue("");
  expect(screen.getByText("안녕하세요")).toBeInTheDocument();
});

it("previews, removes, and sends an image with a caption", async () => {
  const file = new File(["image"], "machine.png", { type: "image/png" });
  vi.spyOn(URL, "createObjectURL").mockReturnValue("blob:machine");
  const revoke = vi.spyOn(URL, "revokeObjectURL").mockImplementation(() => {});
  const onSendMessage = vi.fn();
  render(<ChatRoomPage room={room} messages={[]} onSendMessage={onSendMessage} />);
  fireEvent.change(screen.getByLabelText("이미지 첨부"), { target: { files: [file] } });
  expect(screen.getByAltText("선택한 이미지 미리보기")).toHaveAttribute("src", "blob:machine");
  fireEvent.change(screen.getByPlaceholderText("메시지를 입력하세요..."), { target: { value: "상태 사진입니다" } });
  fireEvent.click(screen.getByRole("button", { name: "전송" }));
  await waitFor(() => expect(onSendMessage).toHaveBeenCalledWith({
    type: "image",
    content: "blob:machine",
    file,
    caption: "상태 사진입니다",
  }));
  expect(screen.queryByAltText("선택한 이미지 미리보기")).not.toBeInTheDocument();
  expect(revoke).not.toHaveBeenCalledWith("blob:machine");
});
```

- [ ] **Step 3: `ChatComposer` 최소 구현**

```tsx
interface ChatComposerProps {
  onSend: (message: PendingChatMessage) => void | Promise<void>;
}
```

내부 상태는 `value`, `selectedFile`, `previewUrl`, `isSending`, `failedMessage`다. `canSend`는 `value.trim().length > 0 || selectedFile !== null`이다. 파일 교체·취소·unmount에서는 소유 중인 URL을 해제하고, 성공 전송된 URL의 소유권은 페이지로 넘겨 composer가 해제하지 않는다.

입력은 한 줄 높이 40px의 `<textarea rows={1}>`로 만들고 Enter 전송/Shift+Enter 줄바꿈을 지원한다. 파일 입력은 다음 접근성 계약을 지킨다.

```tsx
<input ref={fileInputRef} type="file" accept="image/*" aria-label="이미지 첨부" className="sr-only" />
```

- [ ] **Step 4: 페이지에 composer와 로컬 메시지 추가 연결**

`ChatRoomPage`는 props 메시지와 아직 서버에 반영되지 않은 로컬 메시지를 ID 기준으로 병합한다. `onSendMessage`가 정규 `ChatMessage`를 반환하면 그 서버 ID를 사용하고, 반환값이 없는 목 단계에서만 로컬 ID와 현재 시각을 만든다. 채팅방 변경 중 완료된 이전 전송은 새 방에 추가하지 않으며, 전송된 blob URL은 ref의 `Set<string>`에 기록하고 페이지 unmount 시 해제한다.
