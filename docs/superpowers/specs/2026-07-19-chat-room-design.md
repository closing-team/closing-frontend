# 중고거래 채팅방 설계 명세

## 목표

최신 Figma `MKT006`을 기준으로 서버 없이도 상품 정보 확인, 대화 확인, 텍스트 전송, 이미지 선택·미리보기·전송, 실패 후 재시도를 검증할 수 있는 중고거래 채팅방을 구현한다.

## 기준 자료

- Figma 파일: `클로징` (`o64ybsIangaE6hz54R8qSX`)
- 실제 UI 프레임: `1180:8376` (`중고거래_채팅`, 375 × 812)
- 화면설계서: `1288:9209` (`MKT006`)
- Figma UI와 화면설계서가 충돌하면 최신 Figma UI를 시각 기준으로 사용한다.
- Figma에 없는 이미지 선택 후 상태는 사용자가 승인한 보완안에 따라 입력창 위에 작은 미리보기와 삭제 버튼을 표시한다.

## 범위

### 포함

- 상대방 닉네임이 표시되는 상단 바와 뒤로가기 콜백
- 상품 이미지, 제목, 가격이 표시되는 상품 요약 카드
- 상품 요약 카드 선택 콜백
- 날짜 구분선과 상대/내 메시지의 좌우 정렬
- 메시지 시간과 내 메시지의 읽음 표시
- 텍스트 입력, 빈 입력 전송 차단, 전송 후 초기화
- `accept="image/*"` 파일 선택
- 선택 이미지의 로컬 미리보기, 선택 취소, 이미지 전송
- 전송 실패 안내 `메시지를 전송할 수 없습니다.`와 재시도 행동
- 목데이터 기반 기본 상태
- 375px 모바일 화면과 키보드/스크린리더 접근성

### 제외

- 실제 HTTP, WebSocket, SSE 연결
- 인증 토큰 및 사용자 세션 연결
- 프로덕션 채팅 라우트 등록
- 실제 상품 상세 라우트 연결
- 다중 이미지 선택, 촬영, 압축, 업로드 진행률
- 서버 페이지네이션과 과거 메시지 불러오기

API 연결은 별도 작업 7에서 백엔드 명세를 확인한 뒤 수행한다. 이번 화면은 콜백과 데이터 props를 경계로 사용해 목데이터를 나중에 API 데이터로 교체할 수 있게 한다.

## 구조

### `ProductSummaryCard`

- 상품 이미지, 제목, 가격을 렌더링한다.
- 전체 카드를 semantic `button`으로 제공한다.
- 선택 시 `onSelectProduct(productId)`를 호출한다.

### `ChatComposer`

- 제어 입력 `value`, `onChange`, `onSend`를 사용한다.
- 텍스트의 앞뒤 공백을 제거했을 때 내용이 있거나 이미지가 선택된 경우에만 전송 버튼을 활성화한다.
- 숨겨진 파일 입력을 사용하고 이미지 파일만 허용한다.
- 선택한 이미지에는 `URL.createObjectURL`로 미리보기를 만들고 교체·삭제·unmount 시 URL을 해제한다.
- 이미지와 텍스트가 함께 있으면 텍스트를 이미지의 캡션으로 전송한다.
- 전송 성공 시 부모가 입력값과 선택 이미지를 초기화한다.
- Enter는 전송하고 Shift+Enter는 줄바꿈한다.

### `ChatRoomPage`

- 상품과 메시지를 props로 받을 수 있으며 기본값은 `src/mocks/mockChat.ts`의 목데이터다.
- 메시지는 `sentAt` 오름차순으로 복사 정렬하며 전달받은 배열을 변경하지 않는다.
- 기존 공용 `TopBar`와 `ChatBubble`을 재사용한다.
- 상대 메시지는 아바타와 함께 왼쪽, 내 메시지는 오른쪽에 표시한다.
- 새 텍스트/이미지 메시지는 로컬 상태에 추가한다.
- `onSendMessage`를 데이터 전송 경계로 사용하며, API가 저장한 정규 `ChatMessage`를 반환할 수 있게 한다. 반환된 메시지 ID를 로컬 상태에서도 사용해 이후 서버 동기화 시 중복을 막는다.
- `onSendMessage`가 실패하면 실패 상태를 보존하고 안내 영역과 재시도 버튼을 노출한다.
- `messages` 갱신은 아직 서버에 반영되지 않은 로컬 메시지만 보존해 병합하며, 채팅방이 바뀌면 이전 대화와 작성 초안을 초기화한다.
- 재시도 성공 시 실패 안내를 제거하고 입력/이미지를 초기화한다.

## 데이터 계약

```ts
export interface ChatProductSummary {
  id: string;
  title: string;
  price: number;
  imageUrl: string;
}

export interface ChatMessage {
  id: string;
  roomId: string;
  sender: "me" | "other";
  type: "text" | "image";
  content: string;
  caption?: string;
  sentAt: string;
  displayTime: string;
  read: boolean;
}

export type PendingChatMessage =
  | {
      type: "text";
      content: string;
    }
  | {
      type: "image";
      content: string;
      file: File;
      caption?: string;
    };
```

`content`는 텍스트 메시지에서는 문자열이고, 목 이미지 메시지에서는 표시 가능한 이미지 URL이다. 이미지와 텍스트가 함께 전송되면 텍스트는 `caption`으로 표시한다. 실제 업로드 URL 계약은 작업 7에서 API 명세에 맞춰 조정한다.

## 시각 규칙

- 웹 구현에서 Figma의 44px iOS 상태 표시줄은 제외한다.
- 56px 상단 바 아래에 회색 상품 요약 영역을 둔다.
- 상품 이미지는 36 × 36, 카드 내부 여백은 16px, 제목/가격은 12px이다.
- 채팅 영역은 16px 좌우 여백과 16px 그룹 간격을 사용한다.
- 내 말풍선은 `primary-500` 배경/흰 글자, 상대 말풍선은 `gray-5` 배경과 `gray-100` 테두리를 사용한다.
- 작성 영역은 하단 고정, 흰 배경, 상단 테두리, 16px 세로/12px 가로 여백을 사용한다.
- 미리보기는 작성 영역 위쪽에 56 × 56 썸네일로 두고 이미지 대체 텍스트와 삭제 버튼을 제공한다.

## 오류 처리

- 공백만 있는 텍스트는 전송하지 않는다.
- 텍스트와 이미지가 모두 없으면 전송 버튼은 disabled다.
- 이미지가 아닌 파일 선택은 반영하지 않는다.
- 전송 실패 시 작성 내용과 이미지 미리보기를 유지한다.
- 실패 안내는 `role="alert"`로 제공하며 `재시도` 버튼은 마지막 실패 payload를 다시 전송한다.
- 재시도 성공 전에는 동일한 실패 메시지를 대화 목록에 중복 추가하지 않는다.

## 테스트 기준

- 상품 카드 정보와 선택 콜백
- 전달받은 메시지의 시간 오름차순 정렬과 원본 배열 비변경
- 상대 메시지 왼쪽/내 메시지 오른쪽 및 읽음 표시
- 빈 입력·공백 입력 전송 차단
- 텍스트 전송 후 메시지 추가 및 입력 초기화
- 이미지 파일 입력 제한, 미리보기, 삭제, 전송 후 초기화
- 전송 실패 시 경고와 payload 유지, 재시도 성공 시 초기화
- 뒤로가기 콜백
- 기존 Task 1 테스트 회귀 없음
