# 스플래시 앱 프레임 정렬 설계

## 배경

`AuthBootstrap`은 인증 확인 중 `SplashPage`를 `App` 대신 렌더링한다. 이 때문에
`App`의 공통 프레임(`max-w-app`, `min-w-[var(--container-app-min)]`,
`min-h-dvh`, 중앙 정렬, 그림자)을 스플래시가 상속하지 않는다.

브라우저에서 1440px 너비로 확인한 결과 홈을 포함한 앱 프레임은 중앙 375px이지만,
스플래시의 보라색 배경은 1440px 전체를 차지했다.

## 목표

- 스플래시의 표시 영역을 홈과 동일한 앱 프레임으로 맞춘다.
- 데스크톱에서는 중앙 최대 375px 영역에만 스플래시 배경을 표시한다.
- 모바일에서는 최소 320px부터 전체 가용 너비를 사용한다.
- 동적 모바일 뷰포트에 맞춰 높이를 `100dvh`로 통일한다.
- 인증 확인·오류·재시도 동작은 변경하지 않는다.

## 변경 설계

`SplashPage` 최상위 `main`에 홈의 `App` 프레임과 같은 레이아웃 규칙을 직접 적용한다.

- `mx-auto`
- `min-h-dvh`
- `w-full`
- `max-w-app`
- `min-w-[var(--container-app-min)]`
- `shadow-sm`
- 기존 `relative`, `overflow-hidden`, `bg-primary-500` 유지

내부 컨테이너의 `min-h-screen`도 `min-h-dvh`로 변경한다. 별도의 공통 프레임
컴포넌트 추출이나 `AuthBootstrap` 구조 변경은 이번 범위에 포함하지 않는다.

## 테스트

1. `SplashPage` 테스트에 최상위 화면이 홈 앱 프레임 클래스와 동적 뷰포트 높이를
   갖는지 검증하는 회귀 테스트를 추가한다.
2. 테스트를 먼저 실행해 현재 구현에서 실패하는지 확인한다.
3. 최소 클래스 변경 후 해당 테스트와 전체 테스트를 실행한다.
4. 린트와 추적 파일 기준 프로덕션 빌드를 실행한다.
5. 브라우저에서 375px 및 1440px 뷰포트로 스플래시 영역을 확인한다.

## 완료 기준

- 1440px 뷰포트에서 스플래시 최상위 영역이 중앙 375px이다.
- 375px 뷰포트에서 스플래시 최상위 영역이 375px 전체를 사용한다.
- 스플래시 높이가 각 뷰포트에서 `100dvh`와 일치한다.
- 기존 인증 부트스트랩 테스트가 모두 통과한다.
