# 로그인 UI 명세

## 목적

Figma `LOG002` 로그인 화면을 프로젝트의 모바일 앱 프레임에 맞춰 구현한다. 실제 카카오 인증 API는 아직 연결하지 않으며, 호출 지점을 props로 분리해 나중에 교체할 수 있게 한다.

## 출처

- Figma 로그인 화면: `1288:8186`
- Figma 화면설계서: `1288:8945`

## 화면 구성

- 중앙에 앱 로고, `클로징` 서비스명, 서브카피를 표시한다.
- `카카오톡으로 시작하기` 버튼을 표시한다.
- 버튼 아래에 이용약관 및 개인정보 처리방침 안내 문구를 표시한다.
- 로고는 저장소의 실제 `src/assets/images/logo.png`를 사용한다.

## 동작

- `onKakaoLogin` prop이 제공되면 버튼 클릭 시 이를 호출한다. 이 함수는 `Promise<LoginResult>`를 반환한다.
- prop이 없으면 기존 사용자의 성공 결과를 반환하는 임시 기본 동작을 사용한다. 실제 API 연동 시 이 기본 함수를 카카오 인증 호출로 바꾼다.
- 기존 사용자(`existing`) 로그인 성공 시 `ROUTES.HOME`으로 이동한다.
- 신규 사용자(`new`) 로그인 성공 시 서비스 약관 동의 경로(`ROUTES.TERMS`)로 이동한다.
- 서비스 약관 동의 화면은 Figma `1288:10338`을 기준으로 필수 약관 3개, 전체 동의, 가입 버튼을 제공한다.
- 전체 동의 또는 필수 약관 3개를 모두 체크한 뒤에만 `동의하고 가입하기` 버튼을 활성화한다. 가입 버튼은 임시로 홈으로 이동하며, 실제 가입 API가 준비되면 이 지점을 교체한다.
- 취소(`cancelled`) 또는 실패(rejected promise) 시 화면 이동 없이 실패 안내와 재시도 가능한 버튼을 유지한다.
- 진행 중에는 버튼을 비활성화하고 중복 호출하지 않는다.

## 범위 제외

- 카카오 SDK 및 백엔드 API 연동
- 실제 회원 정보 또는 토큰 저장
- 약관 전문 보기와 실제 가입 API 연동

## 품질 기준

- Figma의 375px 너비 비율과 공용 토큰/폰트를 사용한다.
- 버튼은 키보드로 조작 가능하고, 오류는 `role="alert"`로 알려준다.
- 다음을 자동 테스트한다: 기본 성공 이동, 신규 사용자 이동, 실패 상태 및 재시도, 진행 중 중복 클릭 방지, 필수 약관 동의 후 가입 진행.
