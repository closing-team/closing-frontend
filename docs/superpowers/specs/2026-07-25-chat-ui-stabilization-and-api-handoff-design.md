# 채팅 UI 안정화 및 API 인계 설계

> 작성일: 2026-07-25
> 담당 범위: CHAT001 채팅 목록, MKT006 중고거래 채팅, LOG002 스플래시
> 기준 자료: Figma `UI Design` 섹션(`727:4484`), 기능명세서, 현재 프런트엔드 코드

## 1. 결론

공유된 Figma에는 작업에 필요한 기본 화면 대부분이 있지만, 요청한 항목이 모두
포함되어 있지는 않다.

- 스플래시: 포함됨. `스플래쉬` 프레임 `733:4647`, 375×812.
- 채팅방 기본 상태: 포함됨. `중고거래_채팅_사진` 프레임
  `1180:8376` 등에 상품 카드, 메시지, 읽음 여부, 메시지 시간, 사진, 입력창이 있다.
- 채팅 목록: 포함됨. `채팅목록` 프레임 `2273:8878`, `987:68812`.
- 빈 채팅 목록: 포함됨. `채팅이 없을 때` 프레임 `2185:8703`.
- 채팅 목록의 상품명: 포함되지 않음. 현재 Figma 행에는 상대 닉네임, 최근 메시지,
  지역, 상대시간, 읽지 않은 메시지 수만 있다.
- 연결 실패 및 상대방 탈퇴 상태: 포함되지 않음. 관련 전용 화면·배너·토스트와
  재연결 동작을 찾을 수 없다.
- Figma의 `toast` 프레임 `2275:10195`, `2275:10198`은 문의 유형·문의 내용 입력
  검증용이며 채팅 연결 오류용이 아니다.

따라서 구현 기준은 **Figma의 시각 체계는 유지하되, 기능명세서의 필수 동작을
우선하는 방식**으로 정한다. Figma에 없는 상품명과 예외 상태는 기존 컴포넌트의
색상·간격·타이포그래피를 재사용해 보완한다.

## 2. 현재 코드 상태

### 채팅 목록

- `ChatCard`는 `productName`을 이미지 대체 텍스트에서만 사용하고 화면에는 표시하지
  않는다.
- 목록 정렬은 `lastMessageAt`을 사용하므로 최신 메시지 순 정렬은 이미 맞다.
- 표시 시간인 `relativeTime`은 `product.timeAgo`에서 가져온다. 이는 상품 등록
  시간이므로 최근 메시지 시간이 아니다.

### 채팅방

- 상품 카드, 텍스트 메시지, 읽음 표시, 시간, 이미지 선택·미리보기, 빈 메시지 전송
  방지, 전송 실패 재시도가 구현되어 있다.
- 실제 이미지 메시지는 현재 로컬 미리보기까지만 가능하며 저장소에는 텍스트만
  추가된다.
- 연결 끊김과 상대방 탈퇴를 표현하는 도메인 상태 및 UI가 없다.

### 스플래시

- `AuthBootstrap`이 인증 확인 중 `SplashPage`를 `App` 바깥에서 렌더링한다.
- 홈을 포함한 `App`은 데스크톱에서 중앙 375px 프레임이지만 스플래시 배경은
  브라우저 전체 너비를 차지한다.
- 상세 변경은 기존
  `docs/superpowers/specs/2026-07-25-splash-app-frame-design.md`를 따른다.

### 테스트와 복제 파일

- 현재 Vitest는 4개 파일, 16개 테스트를 실행하며 모두 통과한다.
- 이름이 ` 2`로 끝나는 테스트는 `*.test.tsx` 패턴에 맞지 않아 실행되지 않는다.
- TypeScript 빌드는 `ChatListPage.test 2.tsx`, `ChatRoomPage 2.tsx`,
  `ChatRoomPage.test 2.tsx` 때문에 실패한다.
- 추적 파일만 분리한 깨끗한 소스에서는 프로덕션 빌드가 통과한다.

## 3. 접근 방식 비교

### A. Figma만 그대로 구현

시각적 일치도는 가장 높지만 상품명과 예외 처리가 빠져 기능명세를 만족하지 못한다.

### B. 기능명세 우선 + Figma 시각 체계 유지

Figma의 375px 앱 프레임, 색상, 타이포그래피, 상품 카드, 메시지 버블 구조를
유지하면서 누락된 상품명과 예외 상태만 추가한다. 기능명세와 현재 코드의 재사용성을
모두 만족하므로 이 방식을 채택한다.

### C. Figma가 보완될 때까지 구현 대기

디자인 의사결정은 줄지만 토요일 마감 전 진행을 막는다. 현재 범위에는 적합하지 않다.

## 4. 1차 PR: UI 안정화

### 4.1 채팅 목록 상품명

채팅 행은 다음 정보 우선순위를 갖는다.

1. 상대 닉네임
2. 상품명
3. 최근 메시지
4. 최근 메시지 시간
5. 읽지 않은 메시지 수

상품명은 한 줄 말줄임으로 표시한다. 상대 닉네임과 상품명은 서로 다른 텍스트
노드로 유지해 스크린 리더가 정보를 구분할 수 있게 한다. 행의 접근 가능한 이름에도
상품명을 포함한다.

Figma에 있던 지역 정보는 도메인 데이터에는 남겨 두되 기본 행의 핵심 정보에서
제외한다. 제한된 99px 높이에서 상품명과 최근 메시지 시간을 동시에 읽을 수 있게
하기 위한 결정이다.

### 4.2 최근 메시지 시간

목록 시간의 유일한 원본은 `lastMessageAt`이다. `product.timeAgo`는 채팅 목록
시간에 사용하지 않는다.

표시 규칙은 다음과 같다.

- 1분 미만: `방금 전`
- 1시간 미만: `N분 전`
- 24시간 미만: `N시간 전`
- 7일 미만: `N일 전`
- 7일 이상이고 같은 연도: `M월 D일`
- 다른 연도: `YYYY. M. D.`
- 파싱할 수 없는 값: 빈 문자열

테스트가 현재 시각에 의존하지 않도록 포매터는 `now`를 선택 인자로 받는다.

### 4.3 연결 실패 및 탈퇴 예외

채팅방 가용 상태를 다음 세 값으로 정의한다.

```ts
export type ChatAvailability = "active" | "disconnected" | "partner-left";
```

- `active`: 기존 입력·전송 동작을 유지한다.
- `disconnected`: 입력기를 비활성화하고
  `채팅 연결이 원활하지 않습니다.` 알림과 `다시 연결` 버튼을 표시한다.
- `partner-left`: 입력기를 비활성화하고
  `탈퇴한 사용자와는 대화할 수 없습니다.` 알림을 표시한다. 재시도 버튼은 없다.

알림은 입력기 바로 위에 표시하고 `role="alert"`를 사용한다. 전송 요청 하나가
실패한 경우에는 기존 `메시지를 전송할 수 없습니다.`와 `재시도` 동작을 유지한다.
연결 상태와 개별 전송 실패를 같은 상태로 합치지 않는다.

### 4.4 스플래시 영역

`SplashPage`의 최상위 요소에 `App`과 같은 프레임 규칙을 직접 적용한다.

- `mx-auto`
- `min-h-dvh`
- `w-full`
- `max-w-app`
- `min-w-[var(--container-app-min)]`
- `shadow-sm`

내부 컨테이너도 `min-h-dvh`를 사용한다. 인증 확인, 최소 노출 시간, 오류,
재시도 동작은 변경하지 않는다.

### 4.5 테스트 및 복제 파일

이름에 ` 2`가 붙은 파일은 바로 삭제하지 않고 먼저 정식 파일과 비교한다.

- 채팅 테스트에서 유효한 시나리오는 정식
  `ChatCard.test.tsx`, `chatTime.test.ts`, `ChatRoomPage.test.tsx`로 옮긴다.
- 현재 라우터와 Zustand 저장소를 우회하는 복제 페이지 API는 채택하지 않는다.
- 정식 파일로 옮긴 테스트가 통과한 뒤 명시적으로 확인한 복제 파일과 복제 자산을
  제거한다.
- 완료 시 `rg --files src -g '* 2.*'` 결과가 비어 있어야 한다.

## 5. 2차 PR: 실제 API 연결

API 계층과 MSW 연결은 백엔드 서버 구현·배포 전에도 진행할 수 있다. 단, endpoint
목록만으로 시작하지 않고 요청·응답 schema와 오류 계약을 먼저 합의해야 한다.
구체적인 구조와 전환 조건은
`docs/superpowers/specs/2026-07-25-msw-first-api-integration-design.md`를 따른다.

실제 서버 전환과 smoke test는 별도 브랜치와 PR에서 진행하며 1차 UI PR과 섞지
않는다.

### 착수에 필요한 백엔드 정보

#### 인증

- 로컬·개발 서버 base URL
- 로그인 시작 및 콜백 방식
- 세션 저장 방식: 쿠키 또는 토큰
- 세션 복원 엔드포인트와 인증 만료 응답
- 탈퇴 사용자 응답 코드

#### 채팅 목록

- 채팅방 ID와 상품 ID
- 상품명과 대표 이미지 URL
- 상대 사용자 ID, 닉네임, 프로필 이미지
- 최근 메시지 내용과 `lastMessageAt`
- 읽지 않은 메시지 수
- 상대방 탈퇴 여부
- 페이지네이션 방식과 정렬 보장 여부

#### 채팅방

- 메시지 ID, 발신자 ID, 종류, 내용, 생성 시각, 읽음 여부
- 텍스트 전송 요청·응답
- 이미지 업로드 방식과 허용 형식·크기
- 과거 메시지 페이지네이션
- 읽음 처리 방식
- 실시간 연결 방식과 재연결 규칙
- 연결 실패, 권한 없음, 존재하지 않는 방, 탈퇴 사용자 오류 코드

위 필드가 빠졌다면 프런트에서 추측해 대체하지 않고 백엔드에 추가를 요청한다.

### 환경 변수

UI 안정화 단계에서는 수동 `.env` 수정이 필요하지 않다. MSW 연동 단계부터 각
개발자는 커밋하지 않는 `.env.local`에 `VITE_ENABLE_MSW=true`를 설정한다.
백엔드가 base URL을 확정하면 `VITE_API_BASE_URL`도 설정한다. 실제 서버 확인 시에는
`VITE_ENABLE_MSW=false`로 바꾼다. 현재 지도 기능을 사용하는 개발 환경은 별도로
`VITE_NAVER_MAP_CLIENT_ID`도 필요하다.

## 6. 테스트 전략

- 단위 테스트: 상품명 노출, 접근 가능한 이름, 시간 포매팅 경계값.
- 컴포넌트 테스트: active/disconnected/partner-left 상태와 입력기 비활성화,
  재연결 버튼.
- 회귀 테스트: 최신순 정렬, 빈 목록, 메시지 그룹, 이미지 선택·전송 실패 재시도.
- 스플래시 테스트: 공통 앱 프레임 클래스와 `min-h-dvh`.
- 전체 검증: `npm test`, `npm run lint`, `npm run build`.
- 시각 검증: 375px과 1440px에서 스플래시, 채팅 목록, 채팅방 확인.

## 7. 배포 및 PR 전략

1. 현재 브랜치에서 UI 안정화 작업을 완료한다.
2. 복제 파일을 정리하고 테스트·린트·빌드를 통과시킨다.
3. 현재 브랜치를 push하고 `dev` 대상 UI PR을 만든다.
4. 요청·응답 계약을 받은 뒤 최신 `dev`에서 MSW/API 연동 브랜치를 새로 만든다.
5. 동일한 API client를 MSW handler로 먼저 검증한다.
6. 백엔드가 준비되면 MSW를 끄고 실제 base URL로 smoke test한 뒤 별도 PR을 만든다.

## 8. 완료 기준

- 채팅 목록에서 상품명이 화면과 접근 가능한 이름에 표시된다.
- 채팅 목록 시간은 상품 시간이 아니라 최근 메시지 시각에서 계산된다.
- 연결 실패와 상대방 탈퇴 상태가 구분되고 입력 가능 여부가 올바르다.
- 스플래시가 데스크톱에서 홈과 같은 중앙 375px 앱 프레임을 사용한다.
- 이름에 ` 2`가 붙은 복제 파일이 남지 않는다.
- 테스트, 린트, 프로덕션 빌드가 통과한다.
- UI PR과 API PR의 범위가 분리된다.
- 화면이 직접 mock 배열을 읽지 않고 실제 API와 MSW가 공유하는 API 계층을 사용한다.
- 실제 API 구현은 백엔드 계약과 오류 코드를 근거로 한다.
